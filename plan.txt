NEXT UP: BACKGROUND HEADLESS BROWSER VERIFICATION (PLAYWRIGHT AUTOMATION)
--------------------------------------------------------------------------------
* Objective: Staff enters Member ID + DOB + Payer -> System opens a background
  headless browser, logs into the provider portal, retrieves live benefits,
  and renders the full breakdown table automatically.

1. Unified Auto-Verify Input Panel in Frontend:
   - Toggle switch on main screen:
     [⚡ Run Background Auto-Verify]  vs  [📄 Manual Document Upload]
   - Input Fields:
     * Insurance Portal Dropdown: [DD CA | DD FEP | Cigna | MetLife | Guardian]
     * Subscriber / Member ID: [____________________]
     * Patient DOB: [MM/DD/YYYY]
     * Patient Name: [Last, First]
   - Button: [⚡ Run Auto-Verify & Generate Breakdown]
   - Live Progress Status Indicator:
     "Launching background runner..." -> "Authenticating into portal..." ->
     "Fetching patient benefits..." -> "AI Clinical Audit in progress..." -> "Done!"

2. Backend Playwright Automation Runner:
   - Headless browser runner hosted on VPS (`automation/payers/`).
   - Navigates to portal login URL and authenticates using saved vault credentials.
   - Enters Patient Subscriber ID and DOB into portal search form.
   - Captures benefits summary (PDF download or HTML DOM snapshot) and pipes it into the existing AI analysis pipeline.

3. Human-in-the-Loop 2FA / OTP Relay Modal:
   - If portal prompts 2FA SMS or email code on login:
     * Runner pauses and triggers live OTP prompt in DentVerify frontend:
       "2FA Code Required: Enter code sent to clinic [phone/email]: [ _____ ] [Verify]"
     * Staff enters code -> runner resumes session and completes patient eligibility retrieval.

NEXT UP (OFF-HOURS UPDATE): LOCKED INSURANCE HUB & STATE-TO-ADDRESS WIRING
--------------------------------------------------------------------------------
* Objective: Make Insurance Name, Claims Address, Phone #, and Payor ID
  READ-ONLY (non-editable) on the Breakdown screen, and editable ONLY inside
  Settings (by Clinic Admin / Website Owner) using a "Master Claims Hub" wiring
  system.

1. Master Claims Hub & Multi-State Wiring (Settings -> Insurance Directory):
   - Problem Solved: Carriers like Delta Dental have many states (CA, TX, PA,
     NY, FL, GA, etc.) that all belong to the same parent hub ("DD Ins") with
     the EXACT SAME Claims Address, Phone #, and Payor ID.
   - Solution ("Claims Hub Wiring"):
     * Create Master Claims Hubs (e.g. `DD Ins`, `DD FEP`, `MetLife`, `Cigna`,
       `Guardian`, `Aetna`) that hold one canonical:
       - Claims Mailing Address
       - Insurance Phone #
       - Electronic Payor ID
       - Clinic Network Status (`In-Network` / `Out-of-Network`)
       - Pre-Set Fee Schedule (e.g., `PPO Fee`, `Premier Fee`, `UCR / Standard Fee`)
         *(Note: "Payment Goes To: Office vs Patient" is NOT pre-set per hub
         because assignment of benefits varies per employer group/policy even
         under the same carrier; it remains extracted per patient breakdown.)*
     * Clinic Admin can "wire" (tag/assign) multiple states or plan aliases
       (e.g. `[DD CA]`, `[DD TX]`, `[DD NY]`, `[DD PA]`, `[DD FL]`, `[Delta Dental PPO]`)
       into a single Master Hub (`DD Ins`).
     * Updating the address, phone number, or fee schedule on `DD Ins` updates
       it once for all wired states automatically.

2. Locked / Non-Editable Insurance Fields & Single Claims Address Display on Breakdown Dashboard:
   - Single Claims Address Location (No Redundancy):
     * Display the Claims Address, Payor ID, and Phone # in ONLY ONE place:
       the dedicated `CLAIMS ADDRESS & PAYOR ID` box (removed redundant address
       copies under the top Carrier Header and under `NETWORK STATUS`).
   - MetLife / Portal Patient Address Bug Prevention:
     * Never allow a patient's or subscriber's residential street address (e.g.
       `1605 JOHNSON PL, FLOWER MOUND, TX` on MetLife printouts) to be used as
       `Claims Address`. Always enforce the Clinic Insurance Directory's institutional
       Claims P.O. Box Address (e.g. `P.O. Box 981282, El Paso, TX 79998-1282`).
   - Remove free-text inline editing from `Ins Company`, `Ins Address`,
     `Ins Ph #`, and `Payor ID` on the Breakdown screen so staff cannot
     accidentally type wrong addresses or phone numbers.
   - Replace free-text editing with a locked "Select Wired Insurance Hub"
     dropdown on the breakdown card (if staff needs to switch e.g. from
     `DD Ins` to `DD FEP`), which automatically populates the locked Address,
     Phone #, Payor ID, Network Status, and pre-set Fee Schedule from Settings.

3. Clinic Admin Pre-Set Network Status & Fee Schedule (Auto-Applied on Upload):
   - In the Clinic's Insurance Hub Settings, the Clinic Admin pre-sets whether
     their clinic is `In-Network` or `Out-of-Network` and what `Fee Schedule`
     applies for each Insurance Hub / wired sub-plan.
   - Automatic Detection During Upload:
     * Staff does NOT need to manually select In-Network or Out-of-Network when
       uploading a breakdown document.
     * The backend (`POST /api/verify`) automatically injects the active clinic's
       pre-set Insurance Hub network mapping into the AI extraction rules and
       post-processing pipeline.
     * As soon as the AI reads the carrier/plan name on the uploaded PDF/image,
       it automatically knows whether that insurance is `In-Network` or
       `Out-of-Network` for that clinic, extracts the matching benefit column
       (In-Network % vs Out-of-Network %), and locks `Network Participation`
       and the pre-set `Fee Schedule` accordingly.

4. Per-Clinic Custom CDT Code Checklist, Sequence Ordering & Per-Clinic AI Prompt:
   - Clickable CDT Code Checklist & Order (`pagkasunod-sunod`):
     * Powered by the built-in locked `CDT_CODE_DICTIONARY` (`CDT - Meaning`),
       the Clinic Admin can simply click/check `[✓]` which CDT codes their
       clinic wants in their breakdown and arrange their exact display order
       (up/down sequence) per category.
   - Dedicated Per-Clinic AI Prompt (`dentverify.practices` in PostgreSQL):
     * Each clinic workspace stores its own customized **CDT AI Prompt**,
       **System Instruction**, and **Selected CDT Code Sequence** in the database
       (managed by the Clinic Admin or Website Owner).
     * All staff members assigned to that clinic automatically use their
       clinic's exact CDT checklist, ordering, and AI prompt.

5. 7-Day (Weekly) Duplicate Patient Verification Check:
   - Validates whether the same patient (`Patient Name + DOB + Carrier`) in the
     active clinic was already verified **within the last 7 days (1 week)**.
   - Within 7 Days: Shows a custom DentVerify modal notice:
     "Kini nga pasyente na-verify na ni [Staff Name] adtong [Date] (sulod sa
     7 ka adlaw). Gusto nimo ablihan ang existing breakdown o mag-verify og bag-o?"
   - After 7 Days (> 1 Week): Automatically allows fresh verification without
     blocking, since patients with a new appointment after a week require an
     updated check of remaining benefits and history.

6. "Verified By" Staff Audit Stamp + Appointment Readiness Status Tag:
   - Automatically stamps **`Verified by: [Staff Full Name] • [Date & Time]`**
     on the Breakdown Dashboard, Excel/PDF Breakdown Sheet, PMS Clinical Note,
     and Clinic History list.
   - Adds a status badge per verification record:
     * `✅ Complete / Ready for Appointment`
     * `⏳ Pending Carrier Call / Fax History`
     * `❌ Policy Termed / Inactive`

7. Direct One-Click `.PDF` File Download with Auto-Naming:
   - Adds a one-click **Download Clean PDF** button that saves the bordered
     breakdown sheet directly as a `.pdf` file without needing the browser print
     setup dialog.
   - Automatically formats the filename as:
     `LastName_FirstName_Carrier_IV.pdf` (e.g., `Smith_John_DeltaDental_IV.pdf`)
     for instant drag-and-drop into Dentrix, Eaglesoft, or Open Dental.

8. Ortho Payment Terms Detection (`Monthly`, `Quarterly`, `Yearly`):
   - AI automatically detects and extracts Orthodontic Payment Terms (`ortho_payment_terms`)
     when present in the breakdown document:
     * e.g., `Monthly`, `Quarterly`, `Yearly`, `Lump Sum / At Banding`, or `N/A` if not stated.
   - Displays `Ortho Payment Terms` alongside `Ortho Coverage %`, `Ortho Max`,
     `Remaining Ortho`, and `Ortho Age Limit` across the Breakdown Dashboard,
     Excel/PDF Sheet, CSV export, and PMS Clinical Note.
