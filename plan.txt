1. HIPAA TECHNICAL SAFEGUARDS COMPLIANCE (45 CFR Part 164)
--------------------------------------------------------------------------------
* § 164.312(a)(1) Access Control:
  - Unique user identification and credential management.
  - Role-Based Access Control (RBAC): Admin vs Clinic Staff.
  - Multi-tenancy: Clinic A cannot view data from Clinic B.
  - Strong password policy enforced (min 10 chars, uppercase, lowercase, numbers, symbols).
  - Bcrypt password hashing (salt rounds: 12).

* § 164.312(a)(2)(iii) Automatic Logoff:
  - Enforce session timeout after 15 minutes of inactivity.
  - Visual warning countdown before auto-logout occurs.

* § 164.312(a)(2)(iv) Data Encryption at Rest:
  - Field-level encryption using AES-256-GCM for all patient identifiers (Patient Name, DOB, Subscriber ID).
  - AES-256-GCM encryption for stored payer portal credentials (usernames, passwords, PINs).
  - Encryption keys stored securely in environment variables, never committed to git.

* § 164.312(b) Audit Controls & Audit Trail:
  - Tamper-evident logging of all ePHI access events:
    [TIMESTAMP] [USER_ID] [OFFICE_ID] [ACTION] [RECORD_ID] [IP_ADDRESS] [USER_AGENT]
  - Actions logged: LOGIN, LOGOUT, AUTO_VERIFY_TRIGGER, ANALYZE_FILE, VIEW_HISTORY_ITEM, EXPORT_EXCEL, DELETE_RECORD.
  - Audit logs are append-only; standard users cannot modify or delete audit trails.

* § 164.312(e)(1) Transmission Security:
  - Full TLS 1.3 / HTTPS enforced via Cloudflare and Nginx.
  - HSTS enabled.

2. DATABASE ARCHITECTURE (POSTGRESQL)
================================================================================

A. practices (Organizations / Clinics)
   - id: UUID (Primary Key)
   - name: VARCHAR(255)
   - subscription_tier: VARCHAR(50) DEFAULT 'pro'
   - created_at: TIMESTAMP WITH TIME ZONE DEFAULT NOW()

B. users (Clinic Accounts)
   - id: UUID (Primary Key)
   - practice_id: UUID (Foreign Key -> practices.id)
   - email: VARCHAR(255) UNIQUE NOT NULL
   - password_hash: VARCHAR(255) NOT NULL
   - full_name: VARCHAR(255) NOT NULL
   - role: VARCHAR(50) DEFAULT 'staff'  -- 'admin' or 'staff'
   - is_active: BOOLEAN DEFAULT TRUE
   - last_login_at: TIMESTAMP WITH TIME ZONE
   - created_at: TIMESTAMP WITH TIME ZONE DEFAULT NOW()

C. payer_credentials (Encrypted Portal Vault)
   - id: UUID (Primary Key)
   - practice_id: UUID (Foreign Key -> practices.id)
   - payer_key: VARCHAR(50) NOT NULL         -- 'delta_dental', 'metlife', 'cigna', 'guardian'
   - username_enc: TEXT NOT NULL             -- AES-256-GCM encrypted
   - password_enc: TEXT NOT NULL             -- AES-256-GCM encrypted
   - tax_id_or_npi: VARCHAR(50)              -- Office NPI/TIN if required by portal
   - extra_data_enc: TEXT                    -- Security questions / PINs encrypted
   - status: VARCHAR(50) DEFAULT 'active'    -- 'active', 'invalid_credentials', 'otp_required'
   - last_used_at: TIMESTAMP WITH TIME ZONE
   - updated_at: TIMESTAMP WITH TIME ZONE DEFAULT NOW()

D. verifications (Persistent Insurance History)
   - id: UUID (Primary Key)
   - practice_id: UUID (Foreign Key -> practices.id)
   - user_id: UUID (Foreign Key -> users.id)
   - source: VARCHAR(50) DEFAULT 'manual_upload' -- 'auto_portal', 'manual_upload'
   - insurance_payer: VARCHAR(255)
   - patient_name_enc: TEXT NOT NULL         -- AES-256-GCM encrypted
   - member_id_enc: TEXT                     -- AES-256-GCM encrypted
   - dob_enc: TEXT                           -- AES-256-GCM encrypted
   - network_status: VARCHAR(100)
   - full_breakdown_json: JSONB NOT NULL     -- Complete structured breakdown data
   - created_at: TIMESTAMP WITH TIME ZONE DEFAULT NOW()

E. audit_logs (Immutable HIPAA Access Logs)
   - id: UUID (Primary Key)
   - user_id: UUID (Foreign Key -> users.id)
   - action: VARCHAR(100) NOT NULL           -- 'LOGIN', 'AUTO_VERIFY', 'VIEW_RECORD', etc.
   - target_id: UUID                         -- verification ID accessed
   - ip_address: VARCHAR(45)
   - user_agent: TEXT
   - metadata: JSONB
   - created_at: TIMESTAMP WITH TIME ZONE DEFAULT NOW()

PHASE 1: DATABASE PROVISIONING & SECURITY CONFIGURATION
--------------------------------------------------------------------------------
[ ] 1. Install PostgreSQL on VPS (already running on host or configure dedicated DB).
[ ] 2. Create dedicated database `dentverify_db` and restricted database user.
[ ] 3. Run initial schema migrations (practices, users, verifications, audit_logs, payer_credentials).

PHASE 2: USER AUTHENTICATION & SESSION MANAGEMENT
--------------------------------------------------------------------------------
[ ] 1. Install auth dependencies: `bcryptjs`, `jsonwebtoken` or `express-session`, `pg`.
[ ] 2. Implement auth endpoints in `server.js`:
       - POST /api/auth/login        (Rate-limited with express-rate-limit)
       - POST /api/auth/register     (Admin/Invite controlled)
       - POST /api/auth/logout       (Clear HttpOnly cookies)
       - GET  /api/auth/me           (Validate session and return user profile)
[ ] 3. Build Login / Registration UI in `public/`:
       - Clean modal / auth view.
       - Protect uploader & auto-verifier so unauthorized users cannot submit requests.

PHASE 3: PERSISTENT HISTORY & HISTORY DASHBOARD
--------------------------------------------------------------------------------
[ ] 1. Modify `POST /api/analyze`:
       - Once Gemini returns the breakdown JSON, encrypt PHI fields.
       - Store record in `verifications` table tagged with `req.user.id`.
[ ] 2. Create history endpoints:
       - GET /api/verifications          (Paginated list: date, payer, patient preview)
       - GET /api/verifications/:id      (Fetch full breakdown JSON)
       - DELETE /api/verifications/:id   (Soft delete / purge with audit log)
[ ] 3. Build History Dashboard Tab in Frontend:
       - Search bar (search by patient name or insurance payer).
       - Date filters.
       - 1-click "Open Breakdown" to restore the matrix cards and Excel download.

PHASE 4: HIPAA HARDENING & VERIFICATION
--------------------------------------------------------------------------------
[ ] 1. Add 15-Minute Inactivity Auto-Logout:
       - Listen for mouse, touch, and keyboard events in `public/app.js`.
       - Display a 60-second warning countdown before ending the session.
[ ] 2. Implement Audit Log Middleware:
       - Every query to `/api/verifications` logs an entry in `audit_logs`.
[ ] 3. Verify Zero-Leakage:
       - Ensure logs (PM2 / Nginx) never write unencrypted patient identifiers.

PHASE 5: UNIFIED AUTO-VERIFY & PORTAL AUTOMATION (TOP INSURANCE PILOT)
================================================================================
OBJECTIVE: Staff enters Member ID + DOB + Payer -> System logs into the portal,
retrieves the live benefits document/HTML, parses it via Gemini, and renders
the full breakdown instantly without manual portal navigation.

A. TARGET TOP PAYERS (PILOT PHASE):
   1. Delta Dental (National / Regional Portal)
   2. MetLife Dental Portal
   3. Cigna Dental Provider Portal
   4. Guardian Dental Portal

B. ARCHITECTURE & COMPONENTS:
   1. Portal Credential Vault (`/settings/portals`):
      - Clinic Admin inputs login username and password per insurance.
      - Passwords encrypted with AES-256-GCM at rest.
      - Status badge: Connected, Credentials Missing, or Login Failed.

   2. Playwright Headless Automation Runner:
      - Modular scrapers under `automation/payers/`:
        * `delta_dental.js`
        * `metlife.js`
        * `cigna.js`
        * `guardian.js`
      - Features: Stealth plugin enabled, rotating browser fingerprints, randomized delays.
      - Flow:
        Step 1: Launch headless browser & navigate to portal login URL.
        Step 2: Enter encrypted credentials & solve captcha if present.
        Step 3: Handle 2FA / OTP relay if requested (see below).
        Step 4: Navigate to "Patient / Member Search".
        Step 5: Fill Subscriber ID, Patient First/Last Name, and DOB.
        Step 6: Capture complete Benefits Summary (PDF download or full DOM snapshot).
        Step 7: Return document buffer to DentVerify AI analysis pipeline.

   3. Real-Time 2FA / OTP Relay (Human-in-the-Loop):
      - When a portal requests SMS or Email OTP during login:
        * Runner sends event via Server-Sent Events (SSE) or WebSocket to client.
        * DentVerify UI displays live modal:
          "2FA Required: Enter the code sent to [clinic phone/email]: [ _____ ] [Submit]"
        * User inputs the code within 120s -> Bot submits OTP and completes session.
      - Optional: Dedicated clinic email auto-reader for 100% automated OTP capture.

   4. Unified Frontend Search Bar (`public/index.html`):
      - Toggle between:
        [⚡ Unified Auto-Verify]  and  [📄 Manual Document Upload]
      - Input fields:
        * Insurance Dropdown: [Delta Dental | MetLife | Cigna | Guardian]
        * Subscriber / Member ID: [____________________]
        * Patient DOB: [MM/DD/YYYY]
        * Patient Name: [Last, First]
      - Button: [⚡ Verify Patient & Generate Breakdown]
      - Live Progress Bar:
        "Connecting to Delta Dental..." -> "Searching subscriber..." -> "Parsing benefits with AI..." -> "Done!"

   5. Seamless Pipeline Handoff:
      - Raw scraped document/text is piped directly into `/api/analyze`.
      - Gemini formats benefits matrix, shared frequencies (D0210/D0330), and coinsurances.
      - Automatically saves to persistent PostgreSQL history under practice.
      - Automatically generates instant Excel export.
