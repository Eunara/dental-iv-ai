NEXT UP: BACKGROUND HEADLESS BROWSER VERIFICATION (PLAYWRIGHT AUTOMATION)
--------------------------------------------------------------------------------
* Objective: Staff enters Member ID + DOB + Payer -> System opens a background
  headless browser, logs into the provider portal, retrieves live benefits,
  and renders the full breakdown table automatically.

1. Unified Auto-Verify Input Panel in Frontend:
   - Toggle switch on main screen:
     [⚡ Run Background Auto-Verify]  vs  [📄 Manual Document Upload]
   - Input Fields:
     * Insurance Portal Dropdown: [DD CA | DD FEP | Cigna | MetLife | Guardian]
     * Subscriber / Member ID: [____________________]
     * Patient DOB: [MM/DD/YYYY]
     * Patient Name: [Last, First]
   - Button: [⚡ Run Auto-Verify & Generate Breakdown]
   - Live Progress Status Indicator:
     "Launching background runner..." -> "Authenticating into portal..." ->
     "Fetching patient benefits..." -> "AI Clinical Audit in progress..." -> "Done!"

2. Backend Playwright Automation Runner:
   - Headless browser runner hosted on VPS (`automation/payers/`).
   - Navigates to portal login URL and authenticates using saved vault credentials.
   - Enters Patient Subscriber ID and DOB into portal search form.
   - Captures benefits summary (PDF download or HTML DOM snapshot) and pipes it into the existing AI analysis pipeline.

3. Human-in-the-Loop 2FA / OTP Relay Modal:
   - If portal prompts 2FA SMS or email code on login:
     * Runner pauses and triggers live OTP prompt in DentVerify frontend:
       "2FA Code Required: Enter code sent to clinic [phone/email]: [ _____ ] [Verify]"
     * Staff enters code -> runner resumes session and completes patient eligibility retrieval.

COMPLETED & LOCKED IN WEBSITE MEMORY:
--------------------------------------------------------------------------------
* Locked Insurance Hub & State-to-Address Wiring (8-Point Upgrade — Completed):
  1. Master Claims Hub & Multi-State Wiring (Settings -> Insurance Directory):
     - Master Claims Hubs (`DD Ins`, `DD FEP`, `MetLife`, `Cigna`, `Guardian`, `Aetna`)
       store one canonical Claims Mailing Address, Insurance Phone #, Electronic Payor ID,
       Clinic Network Status (`In-Network` / `Out-of-Network`), Pre-Set Fee Schedule,
       and wired state aliases (`matchKeys`, e.g., `dd ca, dd tx, dd pa, dd ny, dd fl`).
     - Editable ONLY by Clinic Admin / Website Owner inside the Insurance Hub Directory.
  2. Locked / Non-Editable Insurance Fields on Breakdown Dashboard:
     - `Ins Company`, `Ins Address`, `Ins Ph #`, and `Payor ID` are read-only on the
       Breakdown screen and linked directly to the "Switch Wired Hub" selector.
     - Single canonical `CLAIMS ADDRESS & PAYOR ID` box prevents patient residential
       street addresses from ever replacing institutional Claims P.O. Box addresses.
  3. Clinic Admin Pre-Set Network Status & Fee Schedule (Auto-Applied on Upload):
     - Backend (`POST /api/verify`) automatically injects the clinic's pre-set
       Insurance Hub network rules into the AI extraction pipeline and auto-populates
       the wired hub's Address, Phone #, Payor ID, Network Status, and Fee Schedule.
  4. Per-Clinic Custom CDT Code Checklist, Sequence Ordering (`pagkasunod-sunod`) & AI Prompt:
     - Clinic Admin / Website Owner can check/uncheck (`[✓]`) and reorder (`↑`/`↓`)
       CDT codes from the locked `CDT_CODE_DICTIONARY`, sync to the AI prompt, and
       save per clinic in PostgreSQL (`dentverify.practices.clinic_ai_settings_json`).
  5. 7-Day (Weekly) Duplicate Patient Verification Check:
     - Warns staff via a custom modal if the same patient (`Patient Name + DOB + Carrier`)
       was already verified within the last 7 days (`<= 7 days`), with one-click option
       to open the existing breakdown or verify a new one anyway.
  6. "Verified By" Staff Audit Stamp + Appointment Readiness Status Tag:
     - Stamps `Verified by: [Staff Full Name] • [Date & Time]` and an interactive
       Appointment Readiness Status badge (`✅ Complete / Ready for Appointment`,
       `⏳ Pending Carrier Call / Fax History`, `❌ Policy Termed / Inactive`) across
       the Breakdown Dashboard, Excel/PDF Sheet, PMS Note, and Clinic History.
  7. Direct One-Click `.PDF` File Download with Auto-Naming:
     - One-click **Download Clean PDF (.pdf)** button generates a single-page bordered
       vector PDF named `LastName_FirstName_Carrier_IV.pdf`.
  8. Ortho Payment Terms Detection (`Monthly`, `Quarterly`, `Yearly`):
     - AI detects and extracts `ortho_payment_terms` (`Monthly`, `Quarterly`, `Yearly`,
       `Lump Sum / At Banding`, or `N/A`) across the Breakdown Dashboard, Excel/PDF Sheet,
       CSV export, and PMS Clinical Note.

* Built-in ADA CDT Code Dictionary (CDT - Meaning):
  - All standard CDT codes and their clinical meanings (e.g. D0120, D1110, D4346,
    D0274, D0210/D0330, D4341, D4910, D2391, D2740, D7140, D7210, D9944, D6010, etc.)
    are permanently stored in the website's memory (`CDT_CODE_DICTIONARY`).
  - Read-only / Non-Editable: The CDT Code and Clinical Description (Meaning)
    columns are locked so their standard meanings can never be accidentally altered.
